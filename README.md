# MotionBridge

게임에서 뽑은 모션을 **내 모델**에 자동 리타깃하고, **Max / Maya / Blender** 용으로 내보내는 간이 에디터.

- 소스 모션(FBX / GLB / BVH / .blend) + 내 모델(스켈레톤 있는 FBX / GLB / .blend) → 자동 본 매핑 → 리타깃
- 리타깃을 **실시간으로 조절**: 스케일, 골반(COM) 위치, 루트 회전, 제자리 모드, 발 IK(접지/바닥 높이/골반 낮추기), 본별 회전 보정
- 품질 검수: 발 미끄러짐, 바닥 뚫림, 다리 안 닿음, 회전 튐 구간을 찾아서 클릭하면 그 프레임으로 이동
- 내보내기: 대상 프로그램(Max/Maya/Blender) 체크박스, 형식(BVH / GLB / FBX), **본 구조 포함 여부 체크박스**, 현재 클립 / 모든 클립
- 인간형은 자동 매핑, 크리처/구조물은 "원본 모션 그대로 + 본 구조 포함"으로 본 세팅째 내보내기

**게임에서 바로 추출**도 지원합니다(언리얼 엔진 게임): 게임 폴더를 고르면 암호화 여부를 검사하고, 암호화돼 있을 때만 AES 키 입력을 요구하고, 아니면 바로 애니메이션을 검색·추출합니다.
FBX/GLB/BVH/PSA/.blend 로 이미 뽑아 둔 파일을 직접 열 수도 있습니다.

> 본인이 구매한 게임의 에셋을 개인 학습·제작 참고용으로 쓰세요. 원본 에셋의 재배포/상업적 사용은 저작권·약관 문제가 될 수 있습니다.

## 실행

### 소스에서
```
pip install -r requirements.txt        # numpy, PySide6
python MotionBridge.py                 # GUI
python -m motionbridge info 파일.fbx    # CLI
```

### exe / 설치 프로그램 만들기 (Windows)
```
packaging\build_windows.bat
```
테스트 → PyInstaller → (Inno Setup 이 있으면) 설치 프로그램까지 만듭니다.
설치 프로그램은 **설치 위치를 고르는 페이지**가 있고, 관리자 권한 없이 사용자 폴더에도 설치할 수 있습니다.
GitHub 에 올리면 `.github/workflows/build-windows.yml` 이 같은 일을 자동으로 합니다.
설치 마법사 문구는 영어입니다(Inno Setup 기본). 한국어로 바꾸려면 `Korean.isl` 을 구해 `installer.iss` 의 `[Languages]` 에 추가하세요.

## 게임에서 추출 (탭 "0. 게임에서 추출")

1. **게임 폴더** 지정 → **검사**: `Content/Paks` 의 `.pak` / `.utoc` 를 읽어 암호화 여부, 형식, 크기를 보여 줍니다(수십 GB 파일은 열지 않고 헤더만 읽음).
2. **암호화 안 된 게임**: AES 키 칸이 비활성화되고 바로 진행. **암호화된 게임**: 키가 없으면 진행을 막고, 있으면 형식(0x+64자리 16진수 / Base64)을 검증해서 사용. AES 키는 프로그램이 구해 주지 않습니다 — 게임/빌드마다 달라서 모딩 커뮤니티 자료 등에서 직접 찾아 넣어야 합니다.
3. **UE 버전**, **mappings(.usmap)** 지정(언리얼 5 는 보통 필요). usmap 은 게임을 실행해서 UE4SS / Dumper-7 로 만드는 파일이라 프로그램이 대신 만들 수 없습니다.
4. **종류**를 고르고(애니메이션 PSA / 메시) 검색식(정규식)으로 에셋을 찾아 → 고른 것을 추출 → 추출된 파일을 열기.
   - **메시**는 바로 쓸 수 있게 **FBX / OBJ / GLB** 로 변환해 줍니다. 형식을 체크하고, **리깅 포함**(스켈레톤+스킨) / **리깅 없음**(메시만) / **둘 다**를 고르고, 대상 프로그램(3ds Max / Maya / Blender)에 맞는 축·단위로 나옵니다. 결과 이름은 `이름_rigged.fbx`, `이름_static.fbx`. 원본 PSKX 는 같은 `Models/` 폴더에 함께 놓입니다.
   - 추출 결과는 **`출력 폴더 / 게임 이름 / 캐릭터 이름 / Animations 또는 Models / 파일`** 3단계로만 정리됩니다 (게임 안의 깊은 `Game/Content/…` 경로는 따라가지 않습니다). 게임 이름은 스팀 게임이면 자동으로 읽어 오고(예: `Mortal Shell 2`) 1) 칸에서 고칠 수 있습니다. 캐릭터 이름은 에셋 경로(`…/Enemies/Prisoner/…`)나 파일 이름에서 정하고, '영상으로 찾기'에서는 고른 몬스터 이름을 씁니다. **`Models/`(모델링 데이터)** 와 **`Animations/`(애니메이션 데이터)** 로 나뉘고, '추출된 파일' 목록에는 파일마다 `[모델링 · 리깅 포함]`, `[모델링 · 리깅 없음]`, `[모델링 원본]`, `[애니메이션]` 같은 이름표가 색과 함께 붙습니다.
   - FBX/GLB 변환에는 Blender 가 필요합니다. **OBJ(리깅 없음)** 는 PSK/PSKX 라면 Blender 없이 됩니다. 텍스처가 필요하면 '머티리얼/텍스처 포함'(GLB 경유).
   - 이미 뽑아 둔 PSKX 는 '출력 폴더 내용 불러오기' → 고르고 → '선택한 메시를 위 형식으로 변환'.
   - '출력 폴더' 링크, '선택 항목 위치 열기' 버튼, 목록의 폴더 줄 더블클릭으로 탐색기에서 폴더가 열립니다.
   애니메이션은 **소스 모션으로**, 메시(GLB)는 **타깃 모델로** 열 수 있습니다(스켈레톤+스킨 포함, 체크하면 머티리얼/텍스처도). 메시 기본 검색식은 `/SK…_` 로 시작하는 이름입니다(게임마다 이름 규칙이 달라서 직접 바꿔야 할 수 있음).
   (PSA 한 파일에 스켈레톤과 모션이 함께 있어서 Blender 를 거치지 않고 바로 리타깃됩니다.)

CLI: `python -m motionbridge extract scan --game "D:\...\Sparta"` / `extract list ...` / `extract export ... --out 폴더` (메시는 `--kind mesh --format glb|psk [--textures]`, 변환까지 한 번에: `--kind mesh --to fbx obj --rig both|rigged|static --target max|maya|blender`)
이미 뽑은 파일 변환: `python -m motionbridge mesh SK_Hero.pskx --to fbx --rig both --target max --out 폴더`

실제 추출은 **추출 도우미 `mbextract`** (CUE4Parse = FModel 이 쓰는 라이브러리 기반, `tools/mbextract`)가 합니다.
빌드: .NET 8 SDK + git 이 있는 Windows 에서 `packaging\build_windows.bat`(자동) 또는
```
git clone --depth 1 --recursive https://github.com/FabianFG/CUE4Parse third_party/CUE4Parse
dotnet publish tools/mbextract -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -o tools/mbextract/out
```
도우미가 없어도 나머지 기능은 모두 동작합니다.

> Mortal Shell 2 (Steam 폴더명 `Sparta`) 는 pak/IoStore 가 **암호화돼 있지 않음**을 실제 파일 헤더로 확인했습니다(AES 키 불필요). 다만 UE5 라 mappings(.usmap) 는 필요합니다.

## 게임 속 이름으로 찾기 (리소스 이름이 다를 때)
화면에 보이는 이름(`The Nameless Captive`)과 파일 이름(`SK_Prisoner` 등)이 다를 수 있어서, '영상으로 찾기' 탭의 검수 표 아래에 **게임 속 이름** 칸을 두었습니다. 줄을 고르고 이름(영어/한국어)을 넣어 [이 이름으로 찾기]를 누르면 세 가지 방법을 합쳐 후보를 채웁니다.

1. **게임 글자 사전**: [글자 사전 만들기]가 게임의 `.locres`(번역 글자)를 읽어 `표시 이름 → 내부 키(Enemy_Prisoner_Name)` 를 만들고, 키의 낱말로 메시를 찾습니다. 키가 해시/GUID 인 항목은 단서가 못 되어 건너뜁니다. 한 번만 만들면 됩니다.
2. **낱말·비슷한 말·오타**: 붙여 쓴 이름(`NamelessCaptive`), captive≈prisoner≈convict, nameless≈unnamed, 한국어(포로, 이름 없는 …)와 폴더 이름까지 봅니다.
3. **AI(선택)**: 게임의 이름 목록 안에서만 고르게 합니다(목록 밖 이름은 버립니다).

여러 방법이 같은 메시를 가리키면 점수가 올라가고, 이유가 후보 옆에 적힙니다. 한계: 게임에 `.locres` 가 없거나 키가 전부 해시이면 2·3번에 의지하게 되고, 그래도 못 찾으면 검색 칸에 리소스 이름 일부를 직접 넣어야 합니다.

## 아는 정보를 먼저 적기 (정확도 올리기)
'영상으로 찾기' 탭의 **아는 정보** 칸에 이 영상에 나오는 캐릭터를 한 줄에 하나씩 `게임 속 이름 — 메모` 로 적으면(예: `The Nameless Captive — 보스, 쇠사슬에 묶인 인간형`), 추측 시작 때 다음이 일어납니다.
- 적은 이름을 먼저 리소스 이름으로 바꿔 보고(게임 글자 사전 → 비슷한 말), 그 이름이 AI에게 알리는 이름 목록 맨 앞에 꼭 들어갑니다. AI 질문에도 "이 영상에 이런 캐릭터가 나온다"는 힌트가 들어갑니다.
- AI가 같은 캐릭터를 알아봤으면 확신을 높이고, AI가 '모름'이라 한 줄이 하나뿐이고 알려 준 것도 하나 남았으면 같은 캐릭터로 합칩니다. AI가 놓친 캐릭터는 표에 새 줄로 넣어 줍니다(리소스를 못 찾으면 자동 선택은 하지 않습니다).
- 게임 이름 칸을 비워 두면 0번 탭의 게임 이름을 씁니다. 메모는 영어/한국어 모두 괜찮고, 입력은 다음 실행에도 남습니다.

검수 표 아래의 **선택한 줄 삭제**(줄을 클릭한 뒤)와 **모두 지우기**로 잘못 인식됐거나 직접 추가한 줄을 치울 수 있습니다. 캐릭터 둘 이상을 함께 추출하면 애니메이션은 이름이 가장 어울리는 캐릭터의 폴더(`게임 이름 / 캐릭터 이름 / Animations`)로 들어갑니다.

## 특징·패턴으로 찾기 (이름이 다 틀릴 때)

화면 이름으로 리소스를 못 찾아도, 그 캐릭터의 **특징적인 동작**을 알면 찾을 수 있습니다. "영상으로 찾기" 3) 의 **특징·패턴** 칸에 `7연속 스핀 공격`, `땅 내려찍기`, `점프 후 돌진` 처럼 적고 [특징으로 캐릭터 찾기] 를 누르면:

1. 설명을 동작 낱말(spin/rotate/whirl…, slam/smash…, charge/dash…)로 바꿉니다. 한국어·영어 모두 되고, `7연속` 같은 타수도 읽습니다. [AI도 사용] 를 켜면 AI 가 설명을 영어 낱말로 바꾸는 일만 거듭니다(에셋 이름은 만들지 않음).
2. 모든 애니메이션 이름에서 그 낱말을 찾아 점수를 매깁니다 (파일 이름 > 폴더 이름, 타수가 같으면 가산).
3. 맞는 애니메이션이 많이/정확히 걸리는 **캐릭터 폴더**를 순위로 만들고, 그 캐릭터의 메시를 선택한 줄의 후보로 채웁니다. 예: `스핀 공격` → `AS_Swordman_SpinAttack_01` → Swordman.

5) 의 **설명으로 찾기** 는 같은 검색을 애니메이션 목록에 바로 적용합니다 (고른 캐릭터 안, 또는 [모든 캐릭터에서]). 추출 버튼은 [메시만 추출] / [애니메이션만 추출] / [메시 + 애니메이션 추출] 로 나뉩니다.

## 영상으로 찾기 (탭 "영상으로 찾기", Ctrl+6)

게임 영상(또는 장면 캡처, AnimRef 로 자른 클립)에 나온 캐릭터를 찾아 그 메시/애니메이션을 뽑는 흐름입니다. **AI가 먼저 추측하고, 검수자가 고치는** 방식이라 틀려도 바로잡을 수 있습니다.

1. **입력**: 영상/이미지를 추가하거나 AnimRef 클립 폴더를 고릅니다(클립 옆 `.json`, 폴더의 `library.json`, `분류/묶음` 폴더 이름, 파일 이름 속 분류 단어에서 타격/피격/스킬 같은 분류를 읽음). 영상에서는 원본당 몇 장씩 고르게 뽑습니다(ffmpeg 필요 — 설치 프로그램에는 `imageio-ffmpeg` 로 포함, 이미지 파일은 ffmpeg 없이도 됨).
2. **인식 방식을 검수자가 고릅니다**: **Ollama**(내 PC, 무료, `ollama pull qwen2.5vl:7b` 등으로 모델 설치) 또는 **Claude**(API 키 필요, 더 정확, 호출량만큼 요금). 키는 '이 PC에 저장'을 체크해야만 설정 파일에 남고, 환경변수 `ANTHROPIC_API_KEY` 도 쓸 수 있습니다. Claude 를 쓰면 장면 이미지가 인터넷으로 Anthropic 에 전송됩니다.
3. **캐릭터 추측**: 게임 파일의 `SK_*` 메시 이름 목록(처음 한 번 읽어 `~/.motionbridge/assets.json` 에 저장)을 AI에게 함께 알려 **그 안에서 고르게** 합니다. 한 화면에 여러 마리가 나오면 각각 한 줄로 나옵니다. 메시가 너무 많으면 monster/enemy/boss 폴더만 쓰거나 '이름 필터(정규식)'로 줄입니다.
4. **검수 표**: 장면(캐릭터 위치를 알면 그 부분)과 AI 추측, 메시 후보 목록이 보입니다. AI 확신이 '자동 선택 최소 확신'(기본 60%)보다 낮거나 이름을 모르겠다고 한 캐릭터(예: 이름 없는 보스)는 **메시를 자동으로 고르지 않고** ⚠ 로 표시해 직접 고르게 합니다(엉뚱한 캐릭터로 넘어가는 것을 막음). 틀리면 후보에서 다른 것을 고르거나 검색 칸에 이름 일부를 입력해 찾고, 아닌 줄은 '제외'합니다. AI가 놓친 캐릭터는 '줄 직접 추가'. **고친 결과는 `~/.motionbridge/matches.json` 에 기억**해 다음에 같은 추측이 나오면 그 메시가 맨 앞 후보로 올라옵니다.
5. **검수 확정**: 확정한 메시마다 애니메이션 후보가 점수순으로 나옵니다. 점수는 캐릭터 이름/폴더 일치 + 분류(공격·피격·스킬·연출·회피·사망·걷기·달리기·대기 키워드) + 타수(`3Hit`, `Combo2` 같은 이름)입니다. 분류와 타수는 직접 좁힐 수 있습니다.
6. **뷰포트로 열기 (리타깃 작업)**: 애니메이션 후보를 고르고(Ctrl/Shift 로 여러 개, 더블클릭은 하나) '선택한 애니메이션을 뷰포트로 열기'를 누르면 PSA 로 뽑아 **소스 모션**으로 열고 '1. 파일·매핑' 탭으로 이동합니다. 여러 개는 한 목록(클립)으로 합쳐지고 바꿔 가며 볼 수 있습니다. 스켈레톤이 다른(다른 캐릭터) 것은 함께 열 수 없어 건너뜁니다.
7. **파일로만 추출**: 고른 메시와 애니메이션을 '0. 게임에서 추출' 탭의 형식/리깅/대상 프로그램/출력 폴더 설정 그대로 `Models/`, `Animations/` 로 뽑습니다.

한계: 애니메이션 후보는 **이름과 분류 단어**로만 고릅니다(영상 속 동작과 PSA 의 실제 움직임을 비교하는 것은 아직 없음). AnimRef 의 내부 저장 형식을 몰라 위 단서 방식으로 읽으므로, 분류가 안 읽히면 폴더 구조나 파일을 알려 주세요.

### AnimRef 연결 (연동규격 v1.1)

AnimRef 의 `연동규격_추출툴.md` 를 따릅니다. 프로그램이 켜져 있는 동안 `127.0.0.1` 의 임의 포트에 작은 서버를 열고 `%APPDATA%\AnimRefLink\animtool.json` 에 `app`/`port`/`token`/`pid` 를 씁니다(끝낼 때 지움, 다른 프로그램이 쓴 파일은 건드리지 않음). 이미 다른 MotionBridge 가 연결 중이면 두 번째 창은 연결을 열지 않고, 낡은 파일(비정상 종료)은 무시하고 새로 씁니다.

- 모든 요청은 `X-AnimRef-Token` 헤더가 맞아야 하고(아니면 401), `Host` 가 로컬이 아니면 403. `GET /v1/ping` 도 토큰이 필요합니다.
- `POST /v1/open {"query": "…\\handoff\\<클립>\\query.json"}` — query.json 을 읽어 `clip.video` 영상을 목록에 넣고, `clip.label`(분류)·`hits`(타격 시각, 개수는 타수에 반영)·`character.name`(→ '아는 정보' 칸)을 같이 보여 줍니다. 게임 폴더를 이미 검사해 뒀으면 바로 몬스터 추측을 시작합니다.
- 실시간 연결이 안 될 때는 메뉴 **파일 > AnimRef에서 가져오기…**(Ctrl+Shift+A) 로 query.json 을 직접 고르면 같은 동작을 합니다.
- AnimRef 가 `MotionBridge.exe --handoff "<query.json>"` 으로 실행해도 처리합니다(이미 켜져 있으면 그 창에 넘기고 끝납니다).
- AnimRef 로 결과를 되돌려 보내는 기능은 없습니다(AnimRef 쪽에서 쓰는 곳이 없어 뺐음). AnimRef → MotionBridge 방향의 요청 받기만 합니다.
- 'AnimRef 클립 폴더…' 대화상자는 AnimRef 설정(`%APPDATA%\AnimRef\settings.json`)의 라이브러리/게임/clips 에서 시작합니다. 클립 옆 `*.json` 의 `label_manual`(손으로 고친 분류)을 `ai_label` 보다 먼저 읽습니다.

## 애니메이션 가공: 늘리기 · fps · 구간 · 루프 · 키 압축

찾은 애니메이션을 내보내기 직전에 가공할 수 있습니다. "리타깃" 탭 아래쪽의 **애니메이션 가공**(늘리기·fps·구간·루프·키 압축 전부, 내보낼 때 결과에 적용 — 내보내기 탭의 추가 가공과 같이 쓰면 합쳐지고 같은 항목은 내보내기 탭 값이 우선), "내보내기" 탭의 **추가 가공**, "영상으로 찾기" 5) 의 **추출할 애니메이션 가공**, CLI 의 `--speed/--frames/--seconds/--fps/--trim/--loop/--compress` 가 같은 기능을 씁니다. 아무것도 안 고르면 가공하지 않습니다.

| 항목 | 설명 |
|---|---|
| 길이 | 속도 배율(2=2배 빠르게), 프레임 수, 길이(초) 중 하나로 클립 전체를 늘리거나 줄임. 회전은 slerp, 위치는 선형 보간 |
| fps | 길이(초)를 유지하고 프레임 수만 변경 (30→60 등) |
| 구간 | 시작/끝 프레임만 남김 |
| 루프 이음 | 끝 N프레임을 첫 포즈로 서서히 이음. 루트 이동량은 유지 |
| 키프레임 압축 | 관절마다 회전(기본 0.5°)·위치(기본 0.1cm) 오차 안에서 군더더기 키를 줄임 (Ramer–Douglas–Peucker) |

가공 순서: 자르기 → 늘리기/fps → 루프 이음 → 압축.

형식별 압축 결과: **GLB·커브 JSON**은 남긴 키만 저장하므로 키 수와 파일 크기가 실제로 줄어듭니다. **FBX**는 Blender 가 프레임마다 굽기 때문에 허용 오차를 Blender 단순화 계수로 바꿔 줄입니다(오차 값은 근사). **BVH·Biped(.ms)·PSA**는 프레임마다 값을 쓰는 형식이라 키 수는 줄지 않고 '정리된 모션'이 저장됩니다. 내보낸 뒤에는 최대 오차와 키 수 변화(예: `키 968 → 100`)를 로그에 보여 줍니다.

"영상으로 찾기"에서 추출할 때는 원본 PSA 는 그대로 두고 옆에 `<이름>_edit.psa` 를 하나 더 만듭니다.

**무료 AI**: '인식 방식 → 다른 AI'의 서비스 목록에 🆓 표시 서비스(OpenRouter 무료 자동 선택 · Groq · GitHub Models · NVIDIA NIM 체험)와 Gemini 무료 티어를 넣었습니다. 서비스를 고르면 무료 한도 안내와 **API 키 받는 곳** 링크가 나오고, **모델 목록** 버튼으로 서버가 지금 제공하는 모델을 불러와 고릅니다(이미지를 볼 수 있어 보이는 모델 👁 이 위쪽). 무료 한도·무료 모델은 자주 바뀝니다.

**애니메이션 후보 목록 검색**: '영상찾기' 탭의 후보 목록 위에 **찾는 종류**(몬스터·보스·NPC / 플레이어블 캐릭터)와 **목록에서 거르기**가 있습니다. 종류를 하나만 켜면 그 종류의 애니메이션만 훑어서 검색(설명·특징 검색 포함)이 빨라지고, 거르기 칸에 글자를 쓰면 지금 목록에서 바로 걸러집니다(띄어쓰기는 모두 포함, 대소문자 무시). 가려진 항목은 선택·추출에서도 빠집니다.

**영상 속 동작과 비슷한 순으로 정렬 (동작 비교)**: 이름으로 찾은 후보를 **실제 움직임**으로 다시 줄 세웁니다. 영상찾기 탭의 애니메이션 목록 아래 **🎬 영상 속 동작과 비슷한 순으로 정렬…** 을 누르고, 영상에서 뽑은 3D 동작 파일(AnimRef 의 **AI 모캡 .bvh**)을 고르면 목록 위쪽 40개를 임시로 뽑아 비교해 `동작 87%` 처럼 점수를 붙이고 점수 순으로 정렬합니다. 방식: 본 이름을 자동 매핑해 팔다리·몸통 **뼈 방향**만 비교(키·비율·축·본 이름이 달라도 됨, 캐릭터가 보는 방향 무관) → 길이를 맞춰 **DTW(시간 맞춤)** 로 비교(빠르기가 달라도 같은 동작이면 가깝게) → 좌우 반전(거울) 동작도 같이 봄(↔ 표시). 점수 = 1 − 평균 각도 차/35°. AI 모캡 BVH(SMPL 본 이름: Pelvis/L_Hip/L_Collar/L_Shoulder…)도 자동 매핑되도록 고쳤습니다.

**쉼표 검색 = 모두 포함**: 검색칸에 `character,attack` 처럼 쉼표로 나누면 두 낱말이 **모두** 들어 있는 것만 찾습니다(대소문자 무시). 영상찾기의 목록 거르기·설명으로 찾기(`점프,내려찍기`)·메시 직접 검색, 0번 탭의 검색식(정규식 안의 `a{2,3}` 같은 쉼표는 그대로), AnimRef 라이브러리 검색에서 똑같이 됩니다.

**작업 중 창**: 파일 읽기·추출·내보내기·검색처럼 시간이 걸리는 작업은 0.3초를 넘기면 작은 '작업 중' 창이 뜹니다. 취소할 수 있는 작업(캐릭터 추측, 애니메이션 설명·특징·게임 속 이름 검색)에는 [✕ 취소]가 있고, 나머지는 끝나면 자동으로 닫힙니다.

**취소 표시**: 진행 창에서 ✕/[취소]/Esc 를 누르면 창이 바로 사라지지 않고 **'⏹ 멈추는 중…'** 으로 바뀌었다가, 하던 단계(AI 요청 등)가 실제로 끝나면 닫히고 화면이 풀립니다. 그 사이에는 다른 조작이 잠겨 있습니다.

### 애니메이션 위치 맞추기 (뷰포트에서 끌어 조절)

소스(주황 고스트)는 이제 처음부터 타깃 모델 위에 겹쳐 보입니다(소스 골반이 타깃 골반 자리에 오도록 옮겨서 그림). 그래도 모션이 모델 자리와 어긋나거나 방향이 다르면 뷰포트에서 직접 맞춥니다.

- **Shift + 왼쪽 드래그**: 모션 전체를 바닥 위에서 이동 (골반·발 IK 가 함께 움직임)
- **Ctrl + 왼쪽 드래그**: 모션 시작 위치를 축으로 모션 전체를 회전
- 뷰포트 아래 **왼쪽 드래그** 선택에서 '애니메이션 이동/회전'으로 바꾸면 Shift/Ctrl 없이 끌어도 됩니다.
- 값은 '2. 리타깃 설정'의 **배치 이동 좌우/앞뒤**와 **루트 회전(Yaw)** 에 그대로 반영되어 숫자로도 고칠 수 있고, **배치 초기화** 로 되돌립니다. 내보내기에도 같이 적용됩니다.
- 끄는 동안에는 카메라가 고정됩니다(손을 따라 움직이도록).

### 몬스터 찾기 / 캐릭터 메쉬 찾기

'영상으로 찾기'의 **3) 캐릭터 추측**에서 먼저 방식을 고릅니다.

- **몬스터 찾기** (기본): 영상에서 AI가 몬스터를 추측하고 4) 검수 표에서 확인합니다.
- **캐릭터 메쉬 찾기**: AI 추측과 영상 없이, **캐릭터 모델링 전체를 이름으로 검색**합니다 (쉼표/띄어쓰기 = 모두 포함). 결과는 **리깅됨(SK_ 스켈레탈)이 먼저, 리깅 안 됨(SM_ 스태틱)이 뒤**로 나오고, 콤보로 한쪽만 볼 수도 있습니다. **플레이어블만** 체크하면 player/pc/hero 이름이 든 메시와 같은 폴더의 같은 리그 변형만 남고 애니메이션도 플레이어 것만 봅니다.
  - **애니메이션은 고른 캐릭터에 해당하는 클립만** 나옵니다 (플레이어는 공용 player/pc/hero 클립). 메시를 고르지 않으면 전체 목록이 이름순으로 뜨고, 목록 거르기·설명으로 찾기·분류/타수 좁히기를 그대로 쓸 수 있습니다. 리깅 없는 메시에는 애니메이션이 없습니다.
  - 리깅 없는 메시(SM_)는 캐릭터 폴더/플레이어 이름이 든 것만 이름 목록에 담습니다. 예전에 만든 이름 목록에는 없으니 **에셋 목록 새로 읽기**를 한 번 누르세요. 추출은 같은 방식(PSKX → FBX/OBJ/GLB)이고, 스켈레톤이 없는 메시는 자동으로 '리깅 없음' 판만 만듭니다.
- '뷰포트로 열기'는 모션을 불러온 뒤 **이 탭에 그대로 머뭅니다** (매핑 탭으로 넘어가지 않음).

### 프레임 편집: 영상 편집기처럼 (속도 · 자르기 · 삭제 · 복제 · 정지)

뷰어 타임라인 바로 아래의 **프레임 편집** 줄에서 합니다. AnimRef 의 영상 편집(조각 줄)과 같은 방식입니다. 추출한 모션은 모든 프레임이 키이므로 키 하나하나가 아니라 **프레임 구간** 단위로 만지면 됩니다.

- 모션이 **조각 블록**으로 보입니다. 블록 너비 = 결과에서 차지하는 프레임 수, **파랑 = 느리게 / 주황 = 빠르게 / 회색 = 정지 프레임**. 줄을 클릭하거나 끌면 그 프레임으로 이동합니다 (위 슬라이더와 같이 움직임).
- **구간 고르기** (모든 편집의 대상): 슬라이더로 옮겨서 **[ 시작**(`I`) / **끝 ]**(`O`) 을 누르거나, 줄에서 **Shift+드래그**로 바로 고릅니다. 고른 구간은 밝게 칠해지고 `[ ]` 표시가 붙으며, 끝 프레임까지 **포함**합니다. 표시를 끌어서 다듬을 수 있고, 시작만 찍으면 거기서 **끝까지**, 끝만 찍으면 **처음부터**입니다. 선택이 없으면 지금 프레임이 있는 **조각 전체**가 대상이고, `Ctrl+D` 로 선택을 풉니다. 아래 정보 줄에 "대상: 선택한 구간 11~30프레임, 길이 20프레임"처럼 항상 표시됩니다.
- **길이를 직접 조절** (배수 계산 불필요): 줄 위에서 **마우스 휠** (↑ 길게 = 느리게 · ↓ 짧게 = 빠르게, Shift = 5프레임씩, 연속으로 돌리면 모아서 한 번에 적용), 블록 **오른쪽 끝을 좌우로 끌기**(놓을 때 적용, 끄는 중 프레임 수 표시), **길이** 칸에 숫자 입력, 또는 `=` / `-` 키(1프레임씩). 속도 숫자는 그대로 쓸 수도 있습니다.
- **단축키**: `I` 시작 · `O` 끝 · `Ctrl+D` 선택 해제 · `Delete` 선택 구간 삭제 · `S` 자르기 · `=`/`-` 길이 ±1 (글자 입력 칸에서는 동작하지 않음). **`Ctrl+Z` / `Ctrl+Y` 가 프레임 편집도 되돌리고 다시 합니다** (프레임 편집 줄의 ↶ ↷ 와 같은 기록).
- **속도**: ×0.25 ×0.5 ×1 ×2 ×4 또는 직접 입력 → 대상 구간만 느리게/빠르게 (나머지는 그대로 이어짐). **부드럽게** 는 구간 안에서 속도를 시작값에서 끝값까지 서서히 바꿉니다(가속·감속).
- **✂ 자르기**(지금 프레임에서 조각 나누기) · **🗑 삭제** · **⧉ 복제**(지금 조각을 한 번 더 붙임) · **◀ 앞으로 / 뒤로 ▶**(조각 순서) · **⏸ 정지**(지금 포즈를 N프레임 멈춤).
- **↶ 되돌리기 / ↷ 다시 / 모두 원본으로**. 뷰포트 왼쪽 위에는 지금 재생 중인 **애니메이션 파일(클립) 이름과 메쉬 이름**이 표시됩니다. 편집은 바로 화면에 반영되고(확정 단계 없음), 내보낼 때 그대로 적용됩니다. 리타깃·IK 도 편집된 모션으로 다시 계산됩니다. 내보내기 탭의 '추가 가공' 은 fps·루프 이음·키 압축만 다룹니다.

중간 프레임은 회전은 구면 보간, 위치는 선형 보간으로 만들고, 편집하지 않은 모션은 원본과 정확히 같습니다. 편집은 클립마다 따로 가지며 새 소스를 열면 초기화됩니다.

### 내보내기 폴더 정리 (캐릭터별)

4. 내보내기 탭의 **캐릭터별 폴더로 정리**(기본 켬)를 쓰면 결과가 한 폴더에 쌓이지 않고 **`출력 폴더 / 캐릭터 이름 / Animations`**(BVH · FBX · Biped(.ms/.mbbip) · 커브 JSON 등 모션 파일)와 **`… / Models`**(메시가 든 GLB, 본 구조 JSON)로 나뉩니다. 캐릭터 이름은 추출 폴더 규칙(`…/캐릭터/Animations/파일`)에서 읽고, 아니면 클립 이름(`A_KnightLady_…` → `KnightLady`)에서 정합니다. **캐릭터 폴더 이름** 칸에 직접 적으면 그 이름을 씁니다. 끄면 예전처럼 한 폴더. CLI: `--organize [--char 이름]`. 이미 한 폴더에 쌓인 예전 결과는 옮기지 않으니 필요하면 직접 정리하세요.

## AI 모캡: 영상 한 편 → 사람 3D 모션 (탭 "AI모캡", Ctrl+7)

무료 오픈소스 엔진 **GVHMR**(권장)과 **WHAM**(구형 환경·실험적) 중 골라서, 프로그램 안에서 설치하고 영상에서 모션을 뽑습니다. 결과는 SMPL 뼈대(22관절)의 BVH 로 저장되고 바로 **소스 모션**으로 열립니다. 이후 매핑·리타깃·내보내기는 평소와 같습니다.

1. **엔진 고르기** — 설명과 주의사항(GPU, 라이선스)이 표시됩니다.
2. **상태 확인 / 자동 설치** — 엔진은 리눅스용이라 Windows 에서는 **WSL2(우분투)** 안에 설치합니다. WSL 이 없으면 관리자 PowerShell 에서 `wsl --install -d Ubuntu` 후 재부팅하세요. 자동 설치는 micromamba → 파이썬 환경 → 엔진 소스 → 패키지 → 체크포인트(gdown) 순서이고, 수 GB 를 받아 30분 이상 걸릴 수 있습니다.
3. **SMPL 인체 모델** — 라이선스 동의(무료 가입)가 필요해서 자동으로 받을 수 없습니다. 탭의 버튼으로 가입 페이지를 열고, 받은 폴더(zip 그대로)를 고르면 알맞은 자리에 복사합니다.
4. **영상에서 모션 뽑기** — 영상 고르기 → (삼각대 영상이면 '카메라 고정') → 실행. 결과: `출력폴더/AI모캡/<영상이름>/<영상이름>.bvh` (+ `.npz` 원본 매개변수).

**주의**
- GVHMR 코드와 SMPL 모델은 **비상업(연구·교육) 라이선스**입니다. 상업 프로젝트에는 쓰지 마세요. (WHAM 코드는 MIT 지만 SMPL 은 마찬가지.)
- GVHMR 은 PyTorch CUDA 12.1 기준이라 RTX 50 시리즈에서 안 될 수 있고, WHAM 은 PyTorch 1.11 / CUDA 11.3 이라 RTX 30 이하에서만 잘 됩니다.
- 손가락·표정은 없습니다(몸 22관절).
- **미검증**: 이 개발 환경에는 GPU·WSL·SMPL 파일이 없어서 설치와 실제 추론은 한 번도 돌려 보지 못했습니다. 스크립트 문법(`bash -n`), 경로 변환, SMPL→BVH 변환(수치 왕복), 화면 흐름(가짜 WSL)만 시험했습니다. 설치가 중간에 막히면 로그 마지막 줄을 알려 주세요.

화면 이해용 AI(영상으로 찾기)는 별도입니다: Ollama 모델 받기, Gemini 2.5 Flash 무료 키, OpenRouter 무료(Nemotron 3 Nano Omni 프리셋 포함) 등은 '영상으로 찾기' 탭의 AI 설정에서 고릅니다.

## 3ds Max Biped 로 바로 내보내기

FBX 는 Biped 에 직접 들어가지 않고(.bip 는 비공개 바이너리라 이 프로그램이 직접 쓸 수 없음) FBX → Biped 변환에 손이 한 번 더 갑니다. 내보내기 탭에서 **"3ds Max Biped (.ms)"** 를 체크하면 다음 두 파일이 만들어집니다.

- `<이름>_biped.ms` — 3ds Max 에서 **Scripting > Run Script** 로 실행하는 MaxScript
- `<이름>_biped.mbbip` — 프레임별 회전 데이터 (스크립트와 **같은 폴더**에 두기)

스크립트가 하는 일: Biped 를 모델 키에 맞춰 새로 만들고 → Figure 모드에서 내 모델 바인드 포즈의 팔다리 방향에 맞추고 → 프레임마다 키를 넣고 → 저장 위치를 물어 `.bip` 로 저장. 그 `.bip` 를 Biped 의 Load File 로 다른 Biped 에도 쓸 수 있습니다. 회전은 바인드 포즈 대비 월드 변화량으로 보내서 본 축 방향이 달라도 맞습니다. 리타깃 결과/소스 모션 모두 가능하고, 매핑된 부위만 들어갑니다(Hips 필수). CLI: `--formats bip`.

**미검증**: 3ds Max 가 없는 환경에서 만들어서 MaxScript 는 실행해 보지 못했습니다(데이터 계산과 파일 형식만 시험). Biped 함수 이름·인자는 문서 기준이고, 안 맞는 곳은 스크립트가 실패한 부위를 메시지로 알려 줍니다. Biped 의 팔다리 길이는 내 모델과 달라서 발 미끄러짐이 생길 수 있습니다.

## 3D 뷰: 메시 보기 방식과 단축키

오른쪽 패널의 **메시** 콤보(또는 숫자키)로 고릅니다: `0` 표시 안 함 · `1` 점 · `2` 와이어 · `3` 반투명 · `4` 솔리드 · `5` 머티리얼(GLB 에 머티리얼/텍스처가 있을 때 색·텍스처 표시). `M` 은 순서대로 순환합니다. 뼈대·겹쳐 보기·IK·카메라 따라가기는 체크박스(또는 `B` `G` `T`)로 켜고 끕니다.

| 동작 | 단축키 |
|---|---|
| 소스 모션 / 타깃 모델 열기 | Ctrl+O / Ctrl+Shift+O |
| 프로필 불러오기 / 저장 | Ctrl+Shift+P / Ctrl+S |
| 내보내기 · 종료 | Ctrl+E · Ctrl+Q |
| **실행 취소 / 다시 실행** | **Ctrl+Z** / Ctrl+Y 또는 Ctrl+Shift+Z |
| 자동 매핑 다시 하기 · 설정 기본값 | Ctrl+M · Ctrl+Shift+R |
| 재생/정지 | Space |
| 프레임 이동 | `,` `.` (1프레임) · Ctrl+←/→ (10프레임) · Ctrl+Home/End (처음/끝) |
| 화면 맞추기 | F |
| 탭 이동 | Ctrl+1 … Ctrl+5 |
| 단축키 목록 | F1 |

3D 뷰에 포커스가 있으면 ← → Home End Space 도 프레임 이동/재생에 쓰입니다(목록·표에서는 방향키가 원래 기능대로 동작).
실행 취소는 **리타깃 설정과 본 매핑 편집**을 되돌립니다. 파일 열기·보기 옵션은 대상이 아닙니다. 슬라이더를 끌어서 바꾼 값은 한 번에 한 단계로 묶입니다.

메시 표시는 삼각형을 칠하는 방식이 아니라 표면을 촘촘한 점으로 찍어 음영을 주는 근사 렌더링입니다(큰 메시는 자동으로 단순화해서 재생 중에도 돌아갑니다). 닫힌 메시는 뒷면을 가리지만 열린 메시(천 등)는 가리지 않아 겹쳐 보일 수 있습니다. 작은 틈이 보일 수 있고, 최종 결과물은 내보낸 파일을 Max/Maya/Blender 에서 확인하세요.

## 사용 순서 (GUI)

1. **소스 모션 열기**(게임에서 뽑은 모션) → **타깃 모델 열기**(내 모델)
2. **1. 파일·매핑**: 자동 매핑 결과 확인. 틀린 곳, ⚠ 표시(한쪽만 연결)는 콤보박스로 고칩니다.
3. **2. 리타깃 조절**: 값을 바꾸면 바로 3D 뷰가 갱신됩니다. 파란색 = 내 모델, 주황색 = 원본 모션(겹쳐 보기), 초록 점 = 발이 고정된 곳.
4. **3. 품질 검수**: 경고를 클릭해서 문제 프레임을 확인.
5. **4. 내보내기**: 폴더, 대상 프로그램, 형식을 고르고 내보내기.
6. 마음에 드는 설정은 **프로필 저장** — 본 이름 기준이라 같은 리그에 다시 쓸 수 있습니다.

### 스케일 자동 맞춤 (모션 크기 ≠ 모델 크기일 때)

"3. 리타깃" 탭 **크기 · 위치 · 방향** 의 [모델에 맞춰 스케일 자동 맞춤] 은 소스 모션과 타깃 모델의 크기를 재서 **스케일 배율**을 자동으로 정합니다. 기준은 고를 수 있습니다: **골반 높이**(기본, 걸음 폭·접지에 안정적) / **전체 키**(겉보기 크기) / **다리 길이**(보폭). 세 기준의 소스·타깃 크기와 비율을 모두 보여 주고, 단위가 cm↔m 로 달라도 비율로 계산하므로 그대로 맞춰집니다. 몬스터↔사람처럼 크기·체형 차이가 크면 경고와 함께 다른 기준을 비교해 보라고 안내합니다. 결과는 평소처럼 수동으로 더 다듬을 수 있습니다.

### 내보내기 옵션

| 옵션 | 설명 |
|---|---|
| 리타깃 결과 / 원본 모션 | 내 모델용 결과, 또는 리타깃 없이 원본 스켈레톤+모션 그대로(크리처/구조물) |
| 본 구조 포함 | 끄면 스켈레톤 없이 애니메이션 커브(JSON)만. 이미 같은 이름의 본이 세팅된 리그용 |
| Maya | Y-up, cm, 캐릭터가 +Z 를 바라봄, 오일러 XYZ |
| 3ds Max | Z-up, cm, 캐릭터가 −Y 를 바라봄, 오일러 ZXY |
| Blender | Y-up, m, 오일러 ZXY |
| BVH | Blender 없이 동작. 대상 프로그램별 축/단위 적용 |
| GLB | Blender 없이 동작. 메시·스킨 포함 가능 |
| FBX | **Blender 필요.** 내 모델 파일을 Blender 로 열어 모션을 키프레임으로 굽고 FBX 로 저장(메시·텍스처 포함). 리타깃 결과 전용 |

BVH 를 읽는 방식은 프로그램/버전마다 다릅니다(예: Max 는 보통 Biped 경로, Maya 는 기본 가져오기에 BVH 가 없음). 실무에서는 **FBX 가 가장 무난**합니다 — 그래서 Blender 설치를 권장합니다.
Blender 는 자동으로 찾고(PATH, `C:\Program Files\Blender Foundation\...`), 못 찾으면 내보내기 탭에서 경로를 지정하세요.

### CLI

```
python -m motionbridge retarget --source 모션.fbx --target 내모델.fbx --out 결과 ^
    --presets maya max blender --formats bvh glb fbx --clip all --save-profile 내모델.json
python -m motionbridge retarget --source 모션.fbx --what source --out 원본 --presets blender --formats glb   # 리타깃 없이 변환
python -m motionbridge retarget ... --profile 내모델.json --in-place --scale 1.1
```

## 검증 상태 (솔직하게)

**자동 테스트로 확인됨** (`python tests/run_all.py`, 전부 통과)
- 쿼터니언/오일러 수학, BVH·GLB 읽기/쓰기 왕복, 이름 기반 자동 매핑(Mixamo / UE / Biped 스타일), 좌표계 자동 인식(Y-up/Z-up, m/cm, A/T 포즈)
- 리타깃: 서로 다른 좌표계·단위·비율·T/A 포즈의 합성 휴머노이드 사이에서 본 방향 일치, 발 IK(접지 구간 미끄러짐 0%), 바닥 클램프, 골반 낮추기, 제자리 모드, 부분 매핑
- 프리셋 축/단위(Maya·Max·Blender), 본 구조 제외 모드, 프로필 저장/복원, 다중 클립 배치
- Blender 적용 스크립트의 **수학**(좌표 정합, 본 축 보정, 포즈 기저 계산)을 Blender 의 포즈 평가식으로 시뮬레이션해서 검증
- 3D 뷰어 계산(카메라/투영/장면)과 UI 로직(가짜 Qt 로 실행: 열기→매핑 편집→설정→프로필→내보내기)

**이 개발 환경에서 직접 실행하지 못한 것 — 처음 쓸 때 확인이 필요합니다**
- **추출 도우미(`mbextract`, C#)**: 이 환경에 .NET/NuGet 이 없어 **컴파일도 못 해 봤습니다.** CUE4Parse API 는 버전마다 달라서 컴파일 오류가 날 수 있습니다(오류 메시지를 알려 주면 맞춰 고칠 수 있음). Python 쪽(검사, AES 입력 게이트, 호출/프로토콜, UI)은 가짜 도우미로 시험했습니다.
- **PSA 읽기**: FModel/CUE4Parse 가 내보낸 PSA 형식(기준 포즈는 원본 값, 키는 Y 반전 + 비루트 켤레)을 소스 코드로 확인해 그대로 해석하고, 실제 Mortal Shell 2 PSA 한 개(구르기)로 사람 동작이 나오는 것까지 확인했습니다. 다른 도구가 만든 PSA 는 4가지 관례를 시험하는 대비책으로 읽습니다. 3D 뷰는 사람 슬롯에 매핑된 본만 그립니다. 게임 리그의 카메라·IK·워프·얼굴·천 보조 본은 몸에서 멀리 떨어져 있어 팔이 날아간 것처럼 보이기 때문입니다(데이터는 전부 유지, 오른쪽 아래 '보조 본' 체크로 전부 표시).
- **좌표계 자동 판별**: 상방은 '발→골반'(다리)으로 먼저 잡아 좌표축에 맞춥니다(구부정한 드워프는 골반→머리가 19° 기울어 있어서, 그것만 쓰면 모션 전체가 앞으로 기울어 '공격하며 대각선으로 솟는' 것처럼 보였습니다). 클립 평균 자세가 거의 내내 옆/뒤집혀 있으면 클립 기준으로 다시 잡고 경고를 냅니다. 이름 자동 매핑은 `Dwarf_l_sheepArmR` 같은 소품 본보다 `upperarm_l` 같은 표준 이름을 우선합니다.
- **머티리얼 보기**: 파일에 실제 색/텍스처가 있으면 그것을, 없으면(게임에서 뽑은 PSK 등) 재질(머티리얼)마다 서로 다른 구분 색으로 보여 솔리드와 확실히 구분됩니다. PSK→FBX/GLB/OBJ 변환 때도 재질마다 다른 색을 넣어 Max/Blender 에서도 재질이 구분됩니다. 진짜 게임 텍스처는 '머티리얼/텍스처 포함'(GLB 경유) 추출이 필요하며, 그 경로는 실제 게임 에셋으로는 아직 검증하지 못했습니다.
- **무거운 메시 뷰포트**: 점 표시는 미리 간추린 정점만 스키닝하고, 솔리드/머티리얼은 삼각형 수에 따라 품질(자동/낮음/보통/높음)을 고르며, 재생·드래그 중에는 표면 샘플을 솎고 느리면 더 솎습니다. 화면에서만 단순화하며 내보내기 데이터는 그대로입니다.
- **메시 → FBX/OBJ/GLB 변환**: PSKX 읽기·단위 변환(cm→m, 축은 그대로: CUE4Parse 출력은 이미 오른손 Z-up 에 캐릭터가 −Y 를 봄 — 실제 SK_Dwarf 로 확인)·본 회전 켤레 자동 판별·OBJ 쓰기는 합성 데이터로 시험했습니다. 실제 Blender 에서 메시/아마추어/버텍스 그룹을 만드는 부분(`blender_mesh.py`)은 가짜 bpy 로 흐름만 시험했고 실제 실행은 미검증입니다. 삼각형 방향은 파일에 든 법선과 맞는 쪽으로 정합니다(법선이 없으면 바깥쪽 기준). 정점이 65536개를 넘는 메시도 읽습니다.
- **메시 추출(GLB/PSK)**: 도우미 코드는 컴파일만 확인했고 실제 게임 메시로는 아직 시험하지 못했습니다. CUE4Parse 의 GLB 를 이 프로그램이 타깃 모델로 읽는지도 실제 파일로는 미검증입니다.
- **이번 개편 전부(실데이터 미검증)**: `mbextract inspect` 는 컴파일·실행 모두 못 해 봤고(리플렉션이라 컴파일은 깨지지 않게 썼지만 필드 이름이 맞는지는 실제 CUE4Parse 로 확인 필요 — 스켈레톤이 비어 나오면 모든 파일이 '미확인'으로 보입니다), 보스전 감지는 합성 화면으로만, OBS 화면/리플레이 호출은 실제 OBS 로 시험하지 못했습니다.
- 실제 **Qt 화면**(PySide6 설치 불가). 로직은 가짜 Qt 로 검증했지만 레이아웃/실제 렌더, 그리고 단축키가 위젯 포커스와 충돌하지 않는지(Space, 숫자키 등)는 실행해 봐야 합니다. 메시 표면 렌더링은 numpy 로 이미지를 만드는 부분만 시험했습니다.
- 실제 **Blender** 에서의 FBX 읽기/내보내기 (`blender_scripts/`). 스크립트의 수학과 흐름은 시험했지만 실제 bpy 호출, Blender 버전별 옵션 이름 차이, FBX 축 옵션(`axis_forward/up`)이 Max/Maya 에서 의도대로 보이는지는 미검증입니다. 어긋나면 `core/export.py` 의 `PRESETS` 값만 바꾸면 됩니다.
- **PyInstaller / Inno Setup** 빌드 (Windows 필요).
- **실제 Mortal Shell 2 데이터**. 본 이름 규칙(트위스트/보조 본 등)이 달라 자동 매핑이 일부 틀릴 수 있습니다 — 그럴 때는 매핑 표에서 고치고 프로필로 저장하세요.

## 알려진 한계 / 다음 단계

- FBX 는 Blender 를 거칩니다. Blender 없이 쓰려면 자체 FBX 작성기가 필요합니다(아직 없음).
- 손가락은 매핑·회전 전달만 하고 IK 는 없습니다. 크리처(다리 3개 이상 등)는 발 IK 체인을 자동 구성하지 않습니다(원본 모션 내보내기만 지원).
- 리타깃은 한 클립 전체를 다시 계산하는 방식이라 아주 긴 클립에서는 슬라이더 반응이 느릴 수 있습니다.
- 프롬프트로 "느낌"을 바꾸는 기능(예: "더 무겁게", "더 빠르게")은 아직 없습니다. 지금의 조절 값(스케일, 속도, 회전 보정, 접지)을 LLM 이 고르는 파라미터 연산으로 두는 구조로 붙이는 것이 다음 단계입니다.

## AnimRef 탭 (한 프로그램으로 합침)
AnimRef(게임 영상 → 공격/피격/스킬 클립 수집·분류·자르기·AI 모캡)가 `motionbridge/animref/` 로 들어와 **AnimRef 탭**으로 열립니다.
- 처음 탭을 열 때만 만들어져서 평소 시작이 느려지지 않습니다. 탭을 끌어내 별도 창으로 띄울 수도 있습니다.
- 라이브러리의 **🎯 게임 모션 찾기**(단축키 G, 클립 1개)는 같은 프로그램이므로 별도 연결 없이 바로 **영상찾기** 탭으로 영상을 넘깁니다. 받기만 하고 **몬스터 추측은 자동으로 시작하지 않습니다**(인식 방식을 고른 뒤 직접 시작, 추측 중에는 작은 진행 창이 뜨고 오른쪽 위 **✕**(또는 [취소]·Esc)로 멈출 수 있음). **🦴 AI 모캡**(M)은 영상 속 사람 동작을 3D 모션으로 뽑아 Blender/Max 로 보내는 별개 기능입니다. 버튼과 우클릭 메뉴는 같은 글을 씁니다.
- 라이브러리 위쪽 버튼 줄은 창이 좁아지면 글자 대신 **아이콘만** 보입니다(마우스를 올리면 전체 설명).
- AnimRef 설정/라이브러리는 기존 위치(`%APPDATA%\AnimRef`, `Documents\AnimRef`)를 그대로 씁니다. 따로 설치된 AnimRef 와 같은 데이터를 공유합니다.
- 설치 파일에는 opencv(headless)·Pillow·obsws-python·pynput 만 추가로 들어갑니다. **무거운 AI(torch · ultralytics · CLIP)는 포함하지 않습니다.** 자동 분석(캐릭터 탐지 · AI 분류)은 분석할 때만 **별도 프로세스**로 돌립니다: `Downloads\AnimRef\AnimRef\.venv` 같은 AnimRef 용 파이썬 환경을 자동으로 찾고(못 찾으면 AnimRef 탭 ⚙ 설정 → '분석 환경'에서 `python.exe` 지정), 그 파이썬이 `worker.py` 를 실행해 진행 상황·로그·취소를 주고받습니다. 결과 클립은 평소처럼 라이브러리 폴더에 저장됩니다. 그 환경이 없어도 영상 보기·직접 자르기·타격 나누기·라이브러리·Ollama 판정·OBS 녹화는 됩니다.

### 영상찾기 탭 추가 동작
- **인식 방식(2번 칸)**: Ollama(내 PC) · Claude(API) · **다른 AI(OpenAI 호환)**. 다른 AI 는 서비스를 고르면 주소·기본 모델이 채워집니다 — OpenAI(GPT-4o), Google Gemini(호환 주소), OpenRouter(여러 AI 모음), 내 서버(LM Studio 등, 키 없이도 됨). 이미지를 볼 수 있는 모델이어야 하고, 키는 방식마다 따로 기억하며 "이 PC에 저장"을 체크해야만 파일에 남습니다(환경변수 `OPENAI_API_KEY`/`GEMINI_API_KEY`/`OPENROUTER_API_KEY` 도 인식). [연결 확인]으로 키·모델을 먼저 점검하세요. 영상 이미지가 그 서비스로 전송되고 호출한 만큼 요금이 들 수 있습니다.
- **메시 목록 더블클릭** = 추출 단계 없이 그 메시를 리깅(스켈레톤+스킨)이 든 GLB 로 뽑아 **바로 뷰포트(타깃)로 열기**. Blender 가 필요 없습니다. 애니메이션 더블클릭은 소스 모션으로 열기(기존).
- **플레이어블 캐릭터**: 보스·몬스터와 달리 몸(메시)이 여러 벌이어도 스켈레톤·애니메이션을 공유하므로, 메시 이름 대신 `player / pc / hero / protagonist / fallen` 같은 낱말이 경로에 든 **공용 애니메이션**을 후보로 보여줍니다. 메시 경로에 그런 낱말이 있으면 자동, 아니면 "플레이어블 캐릭터 애니메이션으로 찾기" 체크. 이미지 인식도 플레이어 캐릭터를 알아보도록 질문을 넓혔고, 이름 목록이 길어 줄일 때도 플레이어 이름은 남깁니다. (게임마다 이름 규칙이 달라서 못 찾으면 체크로 직접 켜거나 0번 탭에서 검색하세요.)
- **열기 창 시작 폴더**: 마지막으로 추출한 폴더를 기억해서 `타깃 모델 열기`는 메시(Models), `소스 모션 열기`는 모션(Animations) 폴더에서 바로 시작합니다.

### 스켈레톤으로 정확히 찾기 · 캐릭터 단위 보기 (이번 개편)
이름만 비슷한 엉뚱한 파일이 섞이던 문제를 줄이려고, 파일 **이름이 아니라 안에 든 데이터**를 읽어 확인합니다.
- **읽는 것**: 애니메이션이 어느 스켈레톤을 쓰는지, 프레임 수·길이·트랙(본별 키) 수·압축 여부, 몽타주면 든 시퀀스. 메쉬는 연결된 스켈레톤. (`mbextract inspect` — CUE4Parse 로 읽음)
- **재생 가능 판정**: 스켈레톤이 있고, 프레임/길이가 0 이 아니고, 트랙(또는 압축 데이터)이 있는 것만 '재생 가능'. 몽타주는 시퀀스+스켈레톤이 있어야 합니다. **재생 못 하는 파일은 애니메이션으로 보여주지 않습니다.**
- **0번 탭 → "3-2) 에셋 찾기 · 캐릭터/스켈레톤 보기"**: 기존 폴더 트리는 그대로 두고, 검색하면 `캐릭터(스켈레톤) > 메쉬 / 스켈레톤 / 애니메이션(재생 가능)` 으로 묶어 보여줍니다. 묶는 기준은 경로가 아니라 **실제 스켈레톤 연결**입니다. 확인 안 된 파일은 '미확인'으로 따로 표시합니다.
- **🎮 플레이어블 캐릭터 표시 — 현재 화면에서는 꺼져 있습니다** (인식이 정확하지 않아 뺐고, 정확해지면 다시 켭니다. 코드의 `PLAYER_FEATURE` 스위치 하나로 켜지며 아래 설명은 그때의 동작입니다): 플레이어 캐릭터는 이름 앞에 `🎮 [플레이어블]` 이 붙고 **목록 맨 위**에 모입니다. 이름이 아니라 게임 데이터로 찾습니다 — **[🎮 플레이어 자동 확인]** (자동으로 캐릭터 찾기 끝에 이어서 자동 실행)이
  ① 게임 설정(.ini)의 `GlobalDefaultGameMode` → 게임모드 블루프린트의 `DefaultPawnClass` → 그 폰(과 부모·자식 폰)이 쓰는 스켈레탈 메시 → 그 메시의 스켈레톤을 플레이어로 확인하고, ② `AutoPossessPlayer`(플레이어 0 이 자동 조종)인 폰, ③ 카메라/스프링암이 달린 폰도 근거로 씁니다(약한 근거는 이유에 그렇게 적힘). 항목에 마우스를 올리면 근거가 나옵니다.
  데이터로 확인하지 못했을 때만 *이름·폴더로 추정*(`Player/PC/Hero/Protagonist` 등, 몬스터 말이 섞이면 보류)하며 `🎮? [플레이어블 추정]` 으로 따로 표시합니다. 틀리면 캐릭터를 고르고 **[🎮 플레이어블 표시/해제]** — 직접 정한 것이 항상 우선하고 검사 기록을 지워도 기억됩니다.
  (도우미 `mbextract players` 는 컴파일/실제 게임 검증 전입니다: 게임에 .ini 가 없거나 블루프린트 구조가 다르면 '찾지 못함' 이라고 알리고 이름 추정으로 돌아갑니다.)
- **영상찾기 탭 → [스켈레톤으로 확인]**: AI 가 이름으로 좁힌 후보를 스켈레톤 데이터로 다시 걸러, 연결이 확인된 것(✔)을 앞에 두고 재생 불가·다른 스켈레톤은 뺍니다. 검사 결과는 게임별로 캐시되어 두 번째부터 빠릅니다.
- **라이선스 점검**: CUE4Parse(원래 쓰던 추출 라이브러리 — **이 환경에서 라이선스 원문을 확인하지 못했습니다.** 상업적으로 쓰거나 배포하기 전에 저장소의 LICENSE 를 꼭 직접 확인하세요) · OpenCV(Apache-2.0) 를 씁니다. 이미지 인식 후보로 봤지만 **ultralytics/YOLO 는 AGPL 이라 넣지 않았습니다.** 글자 인식(OCR)이 필요해지면 RapidOCR / EasyOCR / Tesseract(모두 Apache-2.0)가 후보입니다(지금은 쓰지 않음).

### AnimRef: 보스전 자동 녹화
수집하기 탭의 녹화 카드에 **👹 보스전 감지 시작** 이 있습니다.
- **영역만 대충 잡으면 됩니다(보스전 화면 불필요)**: [체력바 영역 지정…]에서 체력바가 뜨는 자리를 넉넉한 네모로 잡으면, 그 안에 '가로로 길고 얇은 바'(긴 가로선 한 쌍 또는 채도 높은 색 띠)가 나타날 때 알아봅니다. 보스전 중 화면으로 잡으면 모양/색도 배워 더 정확해집니다. 가늘고(약 4px) 색이 옅은 체력바도 잡도록 실제 Mortal Shell 2 녹화 클립(보스 있음/없음)으로 맞췄고, 그 클립들에서 보스 있는 구간만 찾는 것까지 확인했습니다(`tests/data/ms2_top_*.png`). 다른 게임은 [지금 화면으로 시험]으로 확인이 필요합니다.
- **사진으로 정확하게 (선택)**: [📷 사진으로 정확하게]에서 체력바가 또렷하게 보이는 스크린샷(직접 찍은 것, 구해 온 것, OBS 현재 화면 모두 가능)을 열어 체력바 전체를 네모로 잡으면, 체력바의 테두리 모양과 채움 색을 배워 정밀 모드로 인식합니다. 체력바를 못 찾는 사진이면 이유를 알려 주고 저장하지 않습니다. 안 해도 쓸 수 있고, [사진 지정 해제]로 일반 모드로 돌아갑니다. 게임을 바꾸면 그 게임 사진으로 한 번 더 지정하세요. 현재 모드(일반/정밀)는 패널 안내 문구에 표시됩니다.
- **원리(정밀 모드)**: 보스 체력바(와 틀)를 한 번 지정해 두면, OBS 가 보내는 화면에서 그 모양(윤곽선 템플릿 매칭)이 나타나는지 봅니다. 체력바 안 색(HSV)으로 남은 체력 비율도 잽니다. 글자 인식은 쓰지 않아 가볍고, 보스 이름 글자가 바뀌어도 상관없습니다.
- **시작**: 체력바가 `시작 유지 시간` 동안 계속 보이면 수동 녹화와 같은 경로로 녹화를 시작합니다. OBS 리플레이 버퍼를 켜 두고 '감지 직전 영상도 저장'을 체크하면 직전 장면이 앞에 붙습니다(원본 파일은 지우지 않음).
- **종료**: ① 체력바가 `종료 유예`(기본 60초) 동안 안 보이면, ② 체력이 거의 0 이 된 뒤 사라지면 `처치 유예`(짧게), ③ 최대 시간. **페이즈 연출(위아래 검은 띠)** 중에는 '안 보인 시간'을 세지 않아, 연출이 끝나고 나서부터 유예를 잽니다. 모든 값은 UI 에서 조정합니다.
- **수동 녹화와의 충돌 방지**: 수동 녹화 중에는 자동으로 시작하지 않고, 자동으로 시작된 녹화도 [녹화 끝내고 분석하기]/단축키로 언제든 직접 끝낼 수 있습니다(그러면 자동 감지는 그 보스전을 다시 건드리지 않음).
- **시험**: [체력바 영역 지정…] (OBS 화면 또는 스크린샷 파일에서 체력바를 끌어 감쌈) → [녹화본으로 감지 시험…] 으로 이미 녹화한 영상에서 보스전 구간을 어떻게 찾는지 먼저 확인할 수 있습니다.
- ⚠ **실제 게임 화면으로는 아직 검증하지 못했습니다.** 합성 화면으로 시작/종료/연출/처치 판단과 수동 녹화 충돌 방지를 시험했을 뿐입니다. 게임 UI 는 투명·애니메이션·해상도 때문에 기준값 조정이 필요할 수 있으니, 처음에는 꼭 [녹화본으로 감지 시험…]으로 맞춰 보세요.

- **체력바 인식이 안 될 때**: 윤곽(틀 모양) 맞춤에 더해, 체력바 안의 **채움 색 띠**(배운 색이 가로로 길게 이어진 띠)로도 체력바를 알아봅니다. 배경이 달라져도 쓸 수 있는 단서입니다. [지금 화면으로 시험(OBS)] 버튼이 윤곽/색 점수를 바로 보여 주고, 감지 중에는 상태 줄에도 점수가 나옵니다. 보스 이름 글자 인식(OCR)은 아직 넣지 않았습니다(필요하면 RapidOCR 등을 추가할 수 있는데, 실제 게임 화면 한 장으로 먼저 확인이 필요합니다).
- **AI 분석 환경 자동 설치**: AnimRef ⚙ 설정 → 분석 환경 → [분석 환경 자동 설치]. 이 PC 의 파이썬(3.9~3.12, 없으면 winget 으로 3.11)으로 전용 환경(`analysis_venv`)을 만들고 torch(NVIDIA 있으면 CUDA)·ultralytics·CLIP 을 설치합니다. 이후 자동 분석이 그 환경을 자동으로 씁니다. 실제 PC 에서의 설치는 이 환경에서 못 해 봤습니다(순서 로직만 가짜 실행기로 시험).

### AnimRef 라이브러리 구조
`녹화 날짜 > 녹화 세션(시작~끝 시각) > 전체 / 타격 / 피격 …`. 한 번의 녹화(수동이든 보스전 자동이든 같음)에서 나온 클립은 원본 영상 경로로 묶이고, 시작 시각은 OBS 파일 이름(`2026-11-09 14-03-22`)에서, 끝 시각은 파일 수정 시각에서 가져옵니다. 날짜·세션 이름은 우클릭으로 바꿀 수 있고(`sessions.json` 에 저장), 원본 영상을 지워도 클립과의 연결 기록은 남습니다. 원본을 못 찾을 때는 클립 생성 시각으로 대신하며 '약'으로 표시합니다.

### 좌표축이 틀어질 때 (리타깃 2번 탭 → 좌표축)
캐릭터가 눕거나 뒤집히거나 옆을 보면 자동 인식이 틀린 것입니다. 이유는 설정 아래 **⚠ 노란 줄**에 나옵니다: ① 골반·머리/목·양쪽 허벅지(위팔) 매핑이 없어서 인식을 못 하고 기본값(Y-up/+Z 앞)을 쓴 경우(Z-up 파일이면 눕습니다), ② 몸통·다리가 좌표축에서 크게 기울어 상방이 비스듬해진 경우(구부정한 괴수형 리그), ③ 좌우 본 매핑이 서로 바뀌었거나 리그가 비스듬한 경우.
**소스/타깃 빠른 수정** 버튼: `↻ 90° 돌리기`(옆을 볼 때, 여러 번 누르면 계속) · `↔ 앞뒤 반전`(뒤돌아 있을 때) · `⇅ 위아래 반전`(거꾸로) · `⤴ 눕히기/세우기 90°`(누워 보일 때) · `자동`(되돌리기). 지금 적용된 축에서 시작해 한 번씩 돌리므로 상방/전방을 직접 고를 필요가 없고, 아래 콤보에도 그대로 반영됩니다.

### 시작 위치 맞춤 (리타깃 2번 탭)
게임 모션은 원점이 아니라 월드 좌표(수 m 떨어진 곳)에서 시작하는 일이 많아, 절대 위치를 그대로 옮기면 골반(COM)과 발이 모델에서 멀리 떨어져 어긋납니다. **"시작 위치를 모델 원점에 맞춤"**(기본 켜짐)은 첫 프레임의 수평 위치를 모델이 서 있는 자리로 옮기고 이동량만 따라갑니다(발 IK 목표도 같이 옮김). 원본 절대 위치가 필요하면 끄거나 CLI 에서 `--abs-start`.

## 원본 영상 목록과 구간 분석 (AnimRef 수집 탭)

- **녹화를 끝내도 바로 분석하지 않습니다.** OBS 녹화(수동·보스전 자동 모두)는 오른쪽 **'원본 영상 목록'**에 쌓입니다(썸네일·날짜·크기·이미 만든 클립 수 표시). 예전처럼 바로 분석하려면 옵션 카드의 "녹화를 끝내면 바로 분석"을 켜세요.
- 목록에서 영상을 고르고 **[전체 분석]**, 또는 더블클릭/**[구간만 분석…]**으로 영상을 보면서 **원하는 구간(여러 개 가능)만** 골라 분석합니다. 구간을 하나도 안 넣으면 전체를 분석합니다. 구간은 1초 이상이어야 하고, 겹치면 합쳐집니다.
- 구간 분석은 구간만 잘라 앱 데이터의 `ranges` 폴더에 두고 분석합니다. 같은 구간은 다시 자르지 않고, 원본 영상은 지우지 않습니다(원본 정리 설정과 무관).
- **AI 분석 환경이 없으면** 오류창 대신 "지금 자동으로 설치할까요?"를 묻고, 설치가 끝나면 하려던 분석을 이어서 자동으로 시작합니다(설정 → 분석 환경 → 자동 설치와 같은 기능).
- **클립 만들기 진행 창**: 타임라인 편집기에서 [✂ 클립 만들기]를 누르면 진행 창이 떠서 단계(영상 자르기 → 미리보기 그림 → 저장), 자르기 퍼센트, 경과 시간, 진행 기록을 보여 주고 [취소]로 중단할 수 있습니다(취소하면 반쪽짜리 파일은 지웁니다).
- **✨ 하이라이트 자동 자르기**: 타임라인 편집기의 [클립 만들기] 옆 버튼. [클립 만들기]는 지정한 구간을 통째로 한 클립으로 자르고, 이 버튼은 AnimRef 의 동작 감지(공격 · 타격 · 피격 · 스킬 · 연출 등)로 클립을 알아서 찾아 여러 개로 잘라 줍니다. 시작점/끝점(I/O)을 지정했으면 그 구간만, 안 했으면 영상 전체를 훑습니다. 진행 창에서 단계·경과 시간을 보고 취소할 수 있고, 원본은 지우지 않으며 만들어진 클립은 원본 영상의 위치로 연결돼 편집기 타임라인에 표시됩니다.
- **영상 제목과 클립 이름**: 원본 영상 목록에서 영상을 고르고 [✏ 이름](또는 F2)으로 제목을 붙이면(예: 이름없는자 보스전), 그 영상으로 만든 클립이 라이브러리·편집기·"이 영상의 클립" 목록에서 **`이름없는자 보스전 00:00:00~00:00:10`** (제목 + 원본에서의 시작~끝)으로 보입니다. 제목은 표시 이름이라 영상 파일은 그대로이고, 비우면 파일 이름으로 돌아갑니다. 제목을 붙인 영상에서 [클립 만들기]를 하면 클립 파일 이름도 그 제목으로 시작합니다. 라이브러리 검색에서도 제목으로 찾을 수 있습니다.

## 뷰포트에서 본 고르기 · 돌리기 (🦴 본 편집)

- 뷰포트 아래 **🦴 본 편집**을 켜면 파츠(매핑된 본) 목록이 계층으로 나타나고, 뷰포트에는 선택할 수 있는 본이 점으로 표시됩니다. 목록에서 클릭하거나 뷰포트의 점을 클릭하면 그 본이 선택(노란 원)되며, 왼쪽 '본별 회전 보정' 콤보도 같은 본으로 맞춰집니다.
- 선택한 본 점 위에서 **끌면** 그 본(과 하위 본 전체)이 카메라 기준으로 돌아갑니다(좌우 끌기=카메라 위 축, 상하 끌기=카메라 오른쪽 축, **Alt+끌기**=시선 방향 비틀기). 빈 곳을 끌면 카메라가 돕니다.
- 돌린 값은 '본별 회전 보정'(X/Y/Z)에 그대로 쌓이므로 미리보기·내보내기에 똑같이 반영되고, Ctrl+Z 로 되돌릴 수 있으며, [이 본 초기화]로 지울 수 있습니다. 루트 Yaw 가 있어도 화면에 보이는 방향대로 돕니다. 전체 프레임에 같은 보정이 걸리며, 프레임마다 다른 보정은 아닙니다.
- **소스 겹쳐 보기에 골반 높이 보정 반영**: '골반 높이(Y)'를 바꾸면 주황색 소스 뼈대도 같이 오르내려서, 타깃과의 위치 차이가 보정 때문인지 모션 때문인지 구분할 수 있습니다.
- **쓰러지는 모션(죽음·다운) 좌표축 오작동 수정**: 클립 대부분이 누워 있어도 시작 자세가 바인드 좌표계에서 서 있으면 좌표계를 다시 잡지 않고 바인드 기준을 유지합니다.
- **파일·폴더 직접 고르기 / 원본 위치 열기**: "녹화해 둔 영상 분석" 카드의 [📄 영상 파일 선택…]은 영상 파일을, [📁 폴더 가져오기…]는 폴더를 골라 그 안의 영상(하위 폴더 포함)을 한꺼번에 분석 목록에 넣습니다(끌어다 놓지 않아도 됨). 원본 영상 목록의 [📂]는 고른 영상이 있는 폴더를 탐색기로 열고 그 파일을 선택해 줍니다(고른 영상이 없으면 녹화 폴더).

## 본 위치·크기 보정과 3ds Max 식 변환 키 (🦴 본 편집)
- 뷰포트에서 본을 고른 뒤 **Q 선택 · W 이동 · E 회전 · R 크기** 키로 도구를 바꿉니다(3ds Max 와 같음). 본 위에 축 화살표(이동·크기)나 고리(회전)가 나오고, 축을 끌면 그 축으로만, 중심을 끌면 자유롭게 바뀝니다. 빈 곳을 끌면 카메라가 돕니다.
- 왼쪽 패널에 **본별 회전 보정**과 함께 **위치 보정(X/Y/Z)**, **크기 보정**이 있습니다. 위치 보정은 부모 본 기준 벡터로 들어가 모션 중에도 부모를 따라 움직입니다(하위 본 전체가 같이 이동). 크기 보정은 그 본 아래 전체(자식 위치와 메시)에 걸립니다. 모두 Ctrl+Z 로 되돌리고 [이 본 초기화]로 지울 수 있으며 프로필에 저장됩니다.
- 전체 프레임에 같은 값이 걸리는 상수 보정입니다(프레임마다 다른 키는 아님). 본 위치는 내보내기에 반영되지만, 메시 크기 보정은 뷰포트 미리보기에서만 보입니다.

## 손 IK: 손이 바닥에 닿을 때만
원본 모션의 **손 높이가 0(바닥) 근처이거나 0 아래로 내려간 구간**에서만, 그 손이 속한 팔(위팔·아래팔)에 IK 를 걸어 손이 바닥을 뚫지 않게 합니다. 손이 0 에서 벗어나면 IK 가 풀리고 원래 모션으로 돌아갑니다(전환은 부드럽게). 바닥을 짚지 않는 동작에는 아무 영향이 없습니다.
- **높이 계산**: `타깃 바닥 + 소스 손의 바닥 대비 높이 × 스케일`. (예전에는 '타깃 손 바인드 위치 + 소스 손 이동량' 이라, 소스는 A 포즈·타깃은 T 포즈처럼 바인드 때 손 높이가 다르면 그 차이만큼 손이 공중으로 끌려갔습니다 — 소스 손 1.3cm 에서 타깃 손 35cm.)
- **수평 위치**: IK 를 끈 결과의 손 위치를 따라가다가, 손이 수평으로 거의 안 움직이는 구간만 한 점에 고정합니다 (구르거나 끌리는 동작에서 손이 얼어붙지 않음).
- 판정: 손 높이 ≤ 팔 길이의 5% 이면 접촉 시작, 12% 를 넘어야 해제. 리타깃 탭의 **'손 IK 사용 (바닥 짚기)'** 로 끕니다. 정보 줄에 `ℹ 손 IK(왼쪽 팔): 바닥에 닿은 N프레임에 적용 · 소스 손 최저 높이 …%` 가 나옵니다 (접촉이 이상하게 잡히면 이 숫자를 보세요).
- 팔이 닿지 않을 만큼 멀면 완전히 펴고 경고를 냅니다. 사람 모양일 때만 쓰이며 같은 스켈레톤 모드에서는 쓰지 않습니다.

- 설치·실행 흐름은 가짜 서버로 시험했고, 실제 PC 에서의 Ollama 자동 설치(OllamaSetup.exe 무음 설치)와 GPT-OSS 응답 품질은 아직 확인 전입니다.

## AI 회의로 애니메이션 찾기 (영상찾기 탭 → 후보 목록 아래 [🧑‍⚖ AI 회의로 찾기…])
여러 AI 가 **같은 영상 장면과 같은 애니메이션 이름 목록**을 보면서 서로 의견을 주고받아 가장 맞는 애니메이션을 고릅니다.
- 고른 영상에서 최대 12컷을 한 장의 **장면 시트**(번호 붙은 컷을 시간 순서로 붙임)로 만들어, **이미지를 보는 AI**(Ollama 비전 모델 · 두 번째 비전 모델 · Claude · 다른 AI)가 직접 봅니다. **GPT-OSS 는 그림을 볼 수 없는 모델**이라, 다른 AI 들이 말한 장면 묘사를 읽고 같은 목록에서 추론합니다(이미지를 보는 AI 가 한 명은 있어야 시작됩니다).
- 1라운드: 보는 AI 가 먼저 묘사+선택, 글 전용 AI 가 그 묘사를 읽고 선택. 2라운드부터: 서로의 선택과 이유를 보고 고치거나 유지(라운드 1~4 설정). 목록에 없는 이름은 버려서 지어내기를 막습니다.

- 회의에 올리는 목록은 지금 목록 위쪽 150개입니다(많으면 작은 모델이 헷갈림). 먼저 캐릭터(플레이어 메시)를 고르거나 설명으로 찾기로 줄여 두세요. 로컬 AI 는 느려서 몇 분 걸릴 수 있습니다.
- 가짜 AI 로 흐름·검증·합의는 시험했지만, 실제 Qwen/GPT-OSS 의 판단 품질은 아직 확인 전입니다.

### 상대 모션에서 짝 찾기 (처형·패리 피니셔·잡기 같은 맞물리는 연출)
영상에 두 캐릭터가 나오면 한쪽(예: 이름 없는 포로)의 모션부터 찾고, 그것과 맞물리는 다른 쪽(플레이어) 모션을 찾습니다.
1. 보스 메시를 고르고 **🥊 피격·그로기·처형 계열만 보기**를 켜 후보를 줄인 뒤, [AI 회의로 찾기]로 영상과 맞는 보스 모션을 고릅니다.
2. 그 모션을 선택하고 **🔗 고른 모션의 짝 찾기**를 누르면, 반대편 캐릭터(보스 ↔ 플레이어)의 모션 중 **길이가 비슷한 것(기본 ±30프레임, 칸에서 바꿈)** 과 **이름이 겹치는 것**을 점수순으로 목록에 올립니다. 길이는 초로 비교하므로 프레임 속도가 달라도 되고, 점수 = 길이 일치 60% + 이름 겹침 40% (+ Execute/Finisher/Parry 같은 짝 낱말 공유 가산). Victim/Attacker/Player/Boss 같은 역할 낱말은 빼고 비교합니다. 길이는 파일 안을 읽어야 알 수 있어 처음엔 시간이 걸리고, 한 번 읽으면 기억합니다.
3. 좁혀진 목록에서 다시 [AI 회의로 찾기]를 눌러 영상과 맞는 것을 고릅니다.
일반 공격은 보스의 피격 모션이 범용이라 짝이 없습니다 — 맞물리는 연출에만 통합니다.

## 같은 이름의 파일이 이미 있을 때 (덮어쓰기 방지)

애니메이션 추출과 내보내기가 같은 설정을 씁니다 (추출 탭·내보내기 탭 어디서 바꿔도 함께 바뀌고 저장됩니다).

| 선택 | 동작 |
|---|---|
| **이전 파일을 다른 이름으로 보관 (기본)** | 기존 파일을 지우지 않고 `이름_old_날짜시간` 으로 이름을 바꿔 두고, 새 파일을 원래 이름으로 저장합니다. 다른 곳에서 그 이름으로 링크한 파일이 계속 최신으로 유지됩니다. |
| 새 파일을 다른 이름으로 | 이전 파일은 그대로 두고, 새 파일에 `_2`, `_3` … 을 붙입니다. |
| 덮어쓰기 | 같은 이름의 이전 파일이 사라집니다. |

내보내기 탭의 버튼에는 현재 정책이 표시되고(`내보내기 (이전 파일 보관)` 등), **다른 이름으로 내보내기…** 로 파일 이름을 직접 정할 수 있습니다. 보관한 파일 목록은 추출 완료 메시지와 내보내기 로그에 나옵니다.

## 3ds Max Biped 내보내기 (.ms → .bip / .max)
내보내기 탭에서 Biped(.ms) 형식을 체크하면 `이름_retarget.ms` 와 `이름_retarget.mbbip`(모션 데이터)이 만들어집니다. 3ds Max 에서 `.ms` 를 실행하면 **저장 위치를 묻지 않고** 자동으로 저장합니다. 같은 이름이 있으면 `_2`, `_3` 을 붙입니다. 모든 프레임·모든 부위에 키를 넣습니다.
- **스키닝된 .max 를 비워 둘 때**: 새 Biped 를 만들어 모션을 넣고 `.ms` 와 같은 폴더에 `이름_retarget.bip` 로 저장합니다.
- **스키닝된 .max 를 고를 때** (내보내기 탭 → '스키닝된 .max'): 그 파일을 열어 안의 Biped(bip > refbone 구조, COM 포함)에 모션을 적용하고, **그 .max 가 있는 폴더**에 `이름_retarget.max` 와 `이름_retarget.bip` 로 다른 이름 저장합니다. 원본 .max 는 건드리지 않습니다. 지금 열린 장면에 저장 안 한 변경이 있으면 먼저 저장할지 묻습니다.
- 모션은 '내 모델 바인드 포즈 대비 월드 회전 변화량'을 Biped 자기 기본 자세에 적용합니다 (refbone 의 키를 bip 에 옮기는 것과 같은 결과). 템플릿 Biped 의 기본 자세가 모델 바인드 포즈와 다르면 스크립트가 경고를 출력합니다.
- 키를 넣은 뒤 프레임 처음·중간·끝에서 부위별 본 방향 오차를 스스로 점검해 Listener(F11)에 `자가 점검` 줄로 출력합니다. 정면 방향도 허벅지 축으로 맞추고 검증합니다.
- 알려진 문제: MaxScript 는 함수 안에서 바깥 함수의 지역변수를 쓸 수 없어서 `No outer local variable references permitted here: pSlot` 컴파일 오류가 났습니다 — 도우미 함수를 모두 최상위로 옮겨 고쳤고, 같은 종류의 오류를 테스트가 정적으로 점검합니다.
- 실제 3ds Max 에서의 실행은 아직 충분히 검증되지 않았습니다 (이 환경에서는 Max 를 실행할 수 없음).

## 척추 본 개수가 다를 때 (리타깃 탭 → 척추 → '척추 개수가 다르면 중간값으로 맞추기')
소스 척추가 3개(척추1·척추2·가슴)인데 타깃 모델은 2개뿐이면 짝이 없는 본이 생깁니다. 이때 골반~목 사이를 **하나의 곡선**으로 보고, 타깃 본마다 자기가 맡은 곡선 구간과 겹치는 소스 구간을 **길이 비율대로** 섞어 넣습니다 (회전은 구면 보간). 곡선 전체가 보존되므로 목 밑·어깨 위치가 소스와 거의 같게 유지됩니다 (합성 테스트: 3→2/3→4/3→5 본, 휨 60° 에서도 오차 척추 길이의 5% 이하. 예전 방식은 3→2 에서 최대 약 10%).
- 3→2, 2→3, 5→3 등 개수 상관없이 동작하고, **슬롯 매핑에서 빠진 척추 본(실제로는 있는데 슬롯이 없는 본)도 같이 움직입니다** — 예전에는 그런 본이 안 움직여서 일부 본에만 휨이 몰렸습니다.
- 개수가 같고 전부 매핑되어 있으면 기존 그대로입니다. 정보 줄에 `ℹ … 척추 곡선 기준으로 소스 N개 → 타깃 M개 본` 이 나옵니다.
- **체크를 끄면** 이름이 맞는 본만 1:1 로 적용합니다 (직접 매핑을 맞춰 쓰는 검수용).

## 같은 스켈레톤이면 본 이름대로 그대로 적용 (몬스터 등 사람이 아닌 캐릭터)
영상찾기에서 같은 스켈레톤을 쓰는 몬스터 메시와 애니메이션을 열었는데 몸이 흩어지거나 축이 돌아가 있던 원인: 리타깃이 **사람 본(골반·팔·다리) 매핑과 사람 기준 좌표축 추정**에 의존하는데, 몬스터는 그 매핑이 안 잡히거나 엉뚱하게 잡혀서 소스 모션(UE 좌표)과 메시(GLB, 다른 좌표축·단위)가 맞지 않았습니다.
이제 소스와 타깃이 **같은 스켈레톤**이면(본 이름이 글자/숫자 기준으로 거의 다 일치 + 부모-자식 일치 + 바인드 포즈 모양이 겹침, 오차 3% 이하) 사람 매핑을 건너뜁니다.
- 모양을 겹쳐서 소스→타깃 **좌표축 회전과 크기 비율을 데이터로 계산**하므로, Z-up/Y-up·센티미터/미터 차이가 있어도 그대로 맞습니다. 발 IK 는 쓰지 않습니다.
- 사람 모양(양쪽 골반·다리·팔이 매핑됨)이면 기존 사람 리타깃을 그대로 씁니다. 리타깃 탭의 **'같은 스켈레톤이면 본 이름대로 그대로 적용'** 체크로 끌 수 있습니다.
- 켜졌으면 정보 줄에 `ℹ 같은 스켈레톤으로 확인 …` 이 나오고, 이름은 같은데 모양이 안 맞아 못 쓴 경우에는 그 이유(예: 좌우 반전)가 경고로 나옵니다.
